# Frank — Feel Lab

## Purpose

The Feel Lab is where a song finds its emotional and musical identity. It is the most technically invisible layer and the most important one for non-musicians.

The user never sees tempo numbers, key names, or genre labels unless they ask. They react to sound, describe feelings, and the system translates.

## The Two Input Modes

### Mode 1: Texture Listening
The system plays short musical textures (~10 seconds each). The user reacts. The system adjusts and plays another. This continues until the user says "yes, that direction."

A texture is not a beat or a full arrangement. It is a mood rendered as sound — sparse, atmospheric, just enough to feel a direction without committing to one.

### Mode 2: Humming
The user can hum a melody, a rhythm, or a vibe directly into the Feel Lab. The system:
1. Records the hum
2. Detects its approximate pitch contour and tempo using Basic Pitch and librosa
3. Responds: "I hear something [description in plain language] — let me find some directions that feel like that"
4. Uses the hum's detected properties to seed the fingerprint and generate matching textures

The hum is stored as part of the project. It can be referenced by the Beat Room.

Both modes can be used in the same session — the user might hum first and then listen to textures to narrow further.

## The Conversation

The Feel Lab conversation uses emotional and sensory language, never musical terms:

Good questions the system asks:
- "Does it feel more like a late-night drive alone or a crowded room where you're the only one standing still?"
- "Is the energy building toward something, or is it sitting in one place?"
- "Close your eyes and imagine the song playing. Are you inside or outside? Moving or still?"
- "The last texture — was it too much, or did it just need to go in a different direction?"

The system never asks:
- "What tempo do you want?"
- "What key are you thinking?"
- "What genre is this?"

## The Musical Fingerprint

The output of the Feel Lab is a structured JSON object — the musical fingerprint. It is never shown to the user. It lives in the project and feeds everything downstream.

```json
{
  "tempo_bpm": 90,
  "tempo_feel": "steady | building | floating | driving",
  "key": "C minor",
  "mode": "minor | major | modal",
  "energy_level": 0.6,
  "density": 0.4,
  "brightness": 0.3,
  "warmth": 0.7,
  "genre_proximity": ["soul", "r&b", "lo-fi"],
  "instrumentation_hints": ["piano", "soft drums", "bass"],
  "reference_texture_id": "uuid",
  "hum_reference_file": "optional-uuid"
}
```

The LLM builds this object progressively through the conversation. It is not generated all at once — it fills in as the conversation progresses. The fingerprint is considered "ready" when the user approves a direction.

## Revisiting the Feel Lab

The Feel Lab can be revisited at any point during production. When a user returns:
- The previous fingerprint and conversation are loaded
- The system shows what was established: "Last time we landed on something warm and slow — like a quiet late-night feeling"
- The user can confirm and continue, or start fresh
- If the fingerprint changes significantly, the Beat Room is notified and can offer to adapt the beat

## Texture Generation

Textures are generated by the backend using MusicGen with a minimal, atmosphere-focused prompt built from the evolving fingerprint. Each texture is:
- 8–12 seconds long
- Atmospheric, not full-arrangement
- Stored with a UUID in Supabase Storage
- Cached — if the same fingerprint parameters produce the same texture, the cached version is reused

Generation takes 10–30 seconds. The UI shows "Finding a sound..." and allows the user to continue the conversation while waiting.
